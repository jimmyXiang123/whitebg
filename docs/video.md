# 演示视频制作方案（`docs/demo.mp4`）

> 目标：替换 2.1.0 之前的旧界面录像，让 README 首屏的动图与当前界面一致。
> 本文是可直接照做的制作单：分镜、时间轴、画面规格、配乐、混音、渲染命令、验收清单。

## 一、主题与一句话定位

**主题**：把一批产品实拍图拖进去，出来就是能直接上架的白底主图。

一句话文案（首屏、也是整片的信息核心）：

> **拖进去，出来就是白底主图**

支撑信息三条：批量、两种模型、全程本地。不承诺"AI 一键出图"这类会被用户证伪的话。

## 二、技术规格

| 项目 | 取值 | 说明 |
|---|---|---|
| 时长 | **20.0 秒**（600 帧） | 5 个镜头 × 4 秒，正好 10 小节（120 BPM） |
| 画幅 | 1280 × 720（16:9） | README 内嵌与手机竖屏横放都清晰；不做 4K，README 用不上 |
| 帧率 | 30 fps | 静止截图为主，30 足够且体积小 |
| 编码 | H.264 / yuv420p / CRF 20 / `+faststart` | GitHub 页面内嵌需要 faststart |
| 音频 | AAC 192k / 44.1kHz 立体声 | — |
| 单帧安全边距 | 四周 ≥ 64px | 任何文字不贴边 |
| 最小字号 | 24px | 720p 下的下限，再小手机上糊 |
| 配色 | 直接取 `whitebg/theme.py` | `#1466E0` 品牌蓝 / `#F4F5F7` 底 / `#14161A` 主文字 |

## 三、分镜（5 镜 × 4 秒）

切点固定在 **0 / 4 / 8 / 12 / 16 秒**，正好每 4 秒换一次和弦，画面与音乐同拍。

| # | 时间 | 画面构成 | 屏上文案 | 动效 | 素材 |
|---|---|---|---|---|---|
| 1 | 0:00–0:04 | 浅灰底，居中标题 + 蓝色胶囊命令 | **白底图转换**／拖进去，出来就是白底主图／`python -m whitebg` | 标题上移 8px + 淡入 400ms；副标题延迟 200ms | 纯排版 |
| 2 | 0:04–0:08 | 左右对比图居中，下方两枚标签 | 原图（任意背景）→ **1200 × 1200 纯白底** | 整图 1.00→1.04 缓慢推近 | `docs/images/before-after.jpg` |
| 3 | 0:08–0:12 | 主界面截图居右，左侧三条卖点竖排 | 拖拽批量／两种模型随意切／全程本地不联网 | 截图从右侧 24px 滑入，三条文案依次淡入（间隔 120ms） | `docs/images/ui.png` |
| 4 | 0:12–0:16 | 完成态截图 + 结果区聚光 | 跑完直接**打开输出文件夹** | 周围压一层淡色、结果区保持原色，500ms 内淡入 | `docs/images/ui-done.png` |
| 5 | 0:16–0:20 | 四枚 Topics 胶囊 + 两行命令 + 仓库地址 | 开源 · MIT · 本地运行<br>`git clone …/whitebg.git` | 胶囊依次淡入（间隔 80ms），整屏轻微上移收尾 | 纯排版 |

**转场**：**硬切**。切点固定在音乐的和弦转换上，配 20px 位移做入场。
实测过 0.3s 与 0.12s 的交叉淡入，都会出现"双重曝光"——上一镜的大标题残留在下一镜的截图上，
所以放弃叠化。平面底色的片子里，硬切反而更利落。

**节奏原则**（来自 `web-design-engineer` 的动效规范）：

- 不做 8 秒的开场 logo 页，首屏就是内容，4 秒内把价值说完
- 每屏只有一个视觉中心，字幕永远不与复杂底图重叠
- 所有缓动走 `ease-out`（0.2, 0, 0, 1），时长 200–500ms，不用回弹

## 四、配乐

**风格**：极简科技 / 氛围流行（minimal tech-ambient）。有温度但不煽情，像产品自己的呼吸。

| 参数 | 取值 | 理由 |
|---|---|---|
| 速度 | **120 BPM，4/4** | 4 秒 = 2 小节，切镜正好落在小节线上 |
| 和声 | Am9 → Fmaj7 → Cmaj7 → G6 → Am9（每 4 秒一个） | 明亮但不欢闹，避免"悲情小调" |
| 配器 | 暖 pad（微失谐三层）+ 正弦 sub + 稀疏马林巴 pluck（每拍 2/4）+ 极轻 air | 无鼓组：鼓一进来就像广告，压不住画面 |
| 密度 | 稀疏，每分钟约 40 个音符 | 观众看的是界面，不是 MV |
| 人声 | **无** | 中英混杂的旁白在无声播放场景（README 自动播放）里没有意义 |

**本次已生成的样音**（`docs/assets/bgm.mp3`，随本次交付一并加入）：

- 时长 20.0 秒、44.1kHz 立体声、192k MP3、470KB
- 实测 **-18.3 LUFS**、真峰值 **-10.0 dBFS**
- 100% 原创合成（`numpy` 生成，无任何采样），**CC0，商用无风险**

## 五、混音与响度

| 项目 | 取值 |
|---|---|
| 母带响度 | **-18 LUFS**（纯配乐、无人声） |
| 真峰值 | ≤ **-3 dBTP**（本次 -10 dBFS，留足余量） |
| 淡入 / 淡出 | 0.4s / 1.4s |
| 若将来加旁白 | 音乐降到 **-24 LUFS**，旁白 **-16 LUFS**，音乐侧链压缩 3~4dB |

> 视频平台（B 站 / YouTube）会自动归一到 -14 LUFS，母带做 -18 不会被二次压缩拉爆。

## 六、渲染管线（可执行）

**不用 AI 文生视频**。这类模型会把界面里的中文画成鬼画符，演示视频反而失真；而且每次重跑结果不一致，改一版文案得重抽一次。

正确做法是**确定性渲染**：截图 → PIL 逐帧绘制 → ffmpeg 编码。

```bash
# 1) 生成配乐（已生成，改文案需重跑）
python tools/make_bgm.py

# 2) 逐帧渲染 + 编码（1280x720 / 30fps / 20s）
python tools/make_video.py

# 3) 校验：解码完整性 + 响度 + 时长
$FF -v error -i docs/demo.mp4 -f null -            # 无输出即解码正常
$FF -nostats -i docs/demo.mp4 -af ebur128=peak=true -f null - | grep -E "I:|Peak:"
$FF -i docs/demo.mp4 2>&1 | grep Duration          # 应为 00:00:20.00
```

单帧绘制要点：

- 文字用 `ImageFont.truetype("msyhbd.ttc")`（Windows 雅黑），**不要用默认位图字体**，中文会糊
- 截图按 `LANCZOS` 缩放，先缩后贴，避免二次插值
- 每帧都是纯函数 `frame(t) -> Image`，同一时间点渲染多次结果必须一致

## 七、验收清单

- [ ] 时长 20.0s ±0.1s，首尾无黑帧
- [ ] 1280×720，30fps，H.264 yuv420p，`faststart` 已置位
- [ ] 任意 3 个随机时间点截图，文字清晰、不贴边、不重叠
- [ ] 屏幕上出现的界面与实际运行的一致（改版后必须重录）
- [ ] 音画同步：5 个切点都落在 "咚" 的位置（和弦转换处）
- [ ] 静音播放也成立（不依赖音频传达信息）
- [ ] 母带 -18 LUFS ±1dB，真峰值 ≤ -3 dBTP
- [ ] 文件 ≤ 3MB（README 加载体验）；本次成片 0.98MB
- [ ] 中文无错字，命令可直接复制粘贴

## 八、后续维护

界面改版后本视频会失效。两个选择：

1. 重跑第六节三条命令，成本约 5 分钟
2. 把视频降级为 GIF（3 秒循环），改版时只换一张截图

改文案只需动 `tools/make_video.py` 顶部的 `SCENES` 列表，时间轴会按 4 秒均分自动重排。
